# 《三乂川》数值系统策划准备清单（v0.7工作稿）

> 本文不是最终数值表，而是进入数值设计前必须确定的基础、依赖顺序和验收方法。
> 当前以 `../../核心文档` 的v0.8已落地规则为底层，以同目录 `改动内容v0.9.md` 的拍板记录为更高优先级。两者冲突时采用v0.9工作稿；未拍板数值继续后置，不得写入核心文档。

---

## 一、先明确数值策划要解决什么

本项目的数值系统需要同时回答五个问题：

1. **一张牌值多少**：1点命潮、1次抽牌机会、1个手牌位和若干秒时间分别能换来多少伤害、防御或运转收益。
2. **一场战斗多难、多长**：玩家预计打出多少张牌，敌人预计完成多少次行动，允许几次操作失误。
3. **一局如何成长**：从第1域到第9域及最终Boss“48兵”前，队伍、牌组、伙伴和饰品应成长到什么程度。
4. **资源如何流动**：纽币、卡牌、升级、饰品、伙伴等级和局外逸尘从哪里来、花到哪里、是否会溢出或枯竭。
5. **如何证明数值合理**：用基准Build、自动模拟、人工测试和埋点数据判断，而不是只凭卡面看起来是否强。

数值策划的核心不是先给全部内容填数字，而是先建立一套稳定的标尺。只要标尺未定，卡牌伤害、敌人生命和商品价格都会互相循环推翻。

## 二、三种推进方式

### 方案A：先做最小战斗闭环（推荐）

先确定开局基准、命潮节奏、目标战斗时长、基础卡和测试敌人，只做前/中/后期少量模板；闭环可玩后，再接九域奖励与经济。

- 优点：最快发现核心战斗是否有趣，改公式的返工成本最低。
- 缺点：前期看不到完整81张三级卡和九域内容。
- 适合当前阶段：v0.7已有战斗结构，但伙伴、敌人、饰品和投放尚未补齐。

### 方案B：先把全部内容填满再统一平衡

先完成全部卡牌、伙伴分支、饰品、敌人和事件，再进行整体配平。

- 优点：较早看到完整内容规模。
- 缺点：缺少基准时会产生大量伪精确数字，后期返工最大。
- 当前不推荐作为第一步。

### 方案C：先做九域经济与成长曲线

先规定每域能获得多少卡、纽币、饰品与伙伴等级，再反推战斗强度。

- 优点：适合玩法已经稳定、只缺投放和平衡的项目。
- 缺点：当前单场战斗价值尚未确定，无法准确计算“一个奖励等于多少战力”。
- 可作为方案A完成后的第二阶段。

**采用顺序：A → C → B。** 先做可测的战斗尺，再做九域Build曲线，最后扩成完整内容。

## 四、P0：填任何战斗数字前必须先拍板的规则

以下不是“以后慢慢调”的数值，而是会改变模型输入的基础规则。未确定前只能做临时测试假设，不能做最终平衡。

| 优先级 | 必须确定的内容 | 至少要输出什么 | 当前影响 |
|--------|----------------|----------------|----------|
| P0 | 开局共享生命与身份差异 | 三个初始身份各自的生命、卡组、饰品或被动 | 决定第一战玩家强度 |
| P0 | 初始牌组 | 每类卡数量、总张数、是否含整备/伙伴牌 | 决定抽到输出、防御和空转牌的概率 |
| P0 | 开局伙伴 | 候选池、初始等级、专属卡与饰品是否立即生效 | 决定固定入组卡和共享生命 |
| P0 | 三域入队流程 | 每域开场从当组3名不重复伙伴中选择1名，最终形成主角+3伙伴 | 决定牌组膨胀和生命成长节点 |
| P0 | 战败推进 | 普通探索战只得金币；精英/Boss按领域损伤1/2/3颗命源石后继续 | 决定命源石真实容错和总奖励量 |
| P0 | 战斗速度规则 | 0.5/1/2倍速；拖牌时最高0.5倍，所有战斗计时共用模拟时钟 | 决定实时制的实际APM与命潮价值 |
| P0 | 伙伴基础卡面 | 9技能与9绝技已有v0.9初始数值，统一使用技能3次蓄势 | 固定加入最多6张伙伴卡，无法忽略 |
| P0 | 新机制定义 | 金身、充能护盾、吸血、蓄力、形态切换的精确定义 | 不定义就无法比较伙伴强度 |
| P0 | 饰品基本内容 | 普通、九源神石、九专属、绝境石的基础机制 | 无法估算饰品战力份额 |

### 4.1 当前文档冲突的处理纪律

v0.6中的“双伙伴、3颗命源石、装备/成装、营地休整、商店修石”等规则已被v0.7拍板内容替代。数值表应直接使用以下新基线：

- 最终四人队，而不是三人队。
- 9颗局外命源石且一般不恢复，而不是3颗并可常规修复。
- 饰品体系，而不是六散件和主副系成装。
- 商店为2卡+1饰品，并提供刷新、删卡和回收。
- 营地为挖掘、锤子、温存三选一。

v0.9整体拍板并落入核心文档前，每张新数值表都应写明“规则版本=v0.9工作稿”，避免程序或策划误用旧接口。

## 五、P1：先建立单场战斗的五把尺

### 5.1 时间尺

先规定每种战斗的目标体验，不要先定敌人血量。

| 战斗层级 | 目标时长 | 敌方预计完成行动数 | 玩家预计主动出牌数 | 允许的重大失误 | 目标体验 |
|----------|----------|--------------------|--------------------|----------------|----------|
| 普通战 | [待定] | [待定] | [待定] | [待定] | 验证基础循环，低消耗通过 |
| 稀有战 | [待定] | [待定] | [待定] | [待定] | 要求针对意图做一次关键应对 |
| 传说战 | [待定] | [待定] | [待定] | [待定] | 小型构筑检验 |
| 域Boss | [待定] | [待定] | [待定] | [待定] | 展示源神石主题与阶段变化 |
| 48兵 | [待定] | [待定] | [待定] | [待定] | 完整Build终局考试 |

需要额外确定：战斗读秒从何时开始、胜负动画是否计时、暂停/慢速选牌是否计入实际时长。

### 5.2 命潮尺

先确定一个最基础的时间价值：

```text
基础回潮时间 = T秒/点
理论每分钟自然命潮 = 60 / T
理论每分钟可打1费牌数 ≈ 60 / T + 其他回潮来源
```

必须记录：

- 开战是否拥有初始命潮，拥有几点。
- 自然恢复是连续值还是整点到账。
- 命潮加速作用于当前正在恢复的一点，还是下一点。
- 达到上限后的溢出是否完全浪费。
- X费、免费、返还、预借和自动出牌的结算顺序。
- 玩家正常反应时间下，平均命潮浪费率应处于什么范围。

命潮确定后，才能给0/1/2/3/X费牌定预算。0费牌并非免费：它仍会占据候选位，并通常触发“打一弃二”。

### 5.3 卡牌机会尺

本作的真正稀缺资源不只有命潮，还有“每组3张中只能主动选1张”的出牌机会。

每张牌至少记录四种价值：

```text
主动价值 = 卡牌主动打出带来的期望收益
弃置价值 = 因常规弃二产生的期望收益或损失
占位成本 = 抽到但不想打时占据候选位造成的损失
循环影响 = 消耗、保留、轻盈、固有、生成牌对后续牌组的影响
```

因此不能只用“伤害/费用”比较卡牌。轻盈、保留、奇巧、激发、能力、消耗和0级卡都必须把牌组循环价值计入预算。

### 5.4 生命尺

先定义“玩家在该阶段能承受多少次标准攻击”，再反推共享生命和敌方攻击。

```text
可承受标准攻击次数 = 共享生命 / 同阶段敌人标准攻击伤害
一次防御牌的价值 = 少承受多少标准攻击
一次治疗牌的价值 = 恢复多少次标准攻击的生命
```

需明确：

- 主角基础生命、每名伙伴加入增量、每级伙伴生命增量。
- 四人队扩大前后的敌方伤害是否同步跳升。
- 每战满血使治疗只具有“本场价值”，其预算不能照搬跨战保血型肉鸽。
- 护盾不自然衰减，但战斗结束清空；估值需要计算未被敌方伤害消耗而形成的溢出浪费。
- 失去生命穿盾，不能与普通受伤使用同一兑换率。

### 5.5 标准效果尺

建立内部统一单位“标准效果值（SEV）”，用于初稿配平。SEV只是设计工具，不显示给玩家。

建议先以“1费一级打击的期望伤害”作为1个输出基准，再规定：

| 效果 | 需要建立的换算 |
|------|----------------|
| 直接伤害 | 1费在无条件下的标准伤害 |
| 护盾 | 考虑未被消耗概率、战斗结束清空与毒伤穿盾后的有效护盾 |
| 治疗 | 考虑满血浪费、重伤和每战满血后的有效治疗 |
| 虚弱 | 减少的敌方期望伤害，而非状态层数本身 |
| 易伤/鼓舞 | 持续窗口内预计覆盖的攻击次数×增伤量 |
| 脆弱/激昂 | 可消耗次数×每次预计放大的伤害 |
| 减速 | 延迟的秒数能多换来多少命潮和出牌机会 |
| 打断 | 被取消行动的期望价值+敌人重选后的风险 |
| 命潮 | 能换来的卡牌效果，扣除溢出概率 |
| 抽牌/轻盈/保留 | 提高关键牌可得率所增加的期望收益 |

换算表的目标是发现明显越界，不要求所有卡牌机械同值。有条件、Build依赖、时机风险和牌组污染的牌可以高于无条件牌，但风险必须可测。

## 六、战斗公式与取整规范

### 6.1 直接伤害

沿用现有乘区结构，并把每个区的上限和来源登记清楚：

```text
有效攻击 = 卡牌基础攻击 + 力量

最终直接伤害 = 基础结算值
               × (1 + 激昂 + 鼓舞)
               × (1 + 易伤 + 脆弱)
               × 独立增伤乘区
```

需要补齐：

- 力量对多段伤害是每段生效、总计生效还是按卡面系数生效。
- 激昂/脆弱在多段牌上消耗1次还是每段消耗。
- 同tick多张牌、自动出牌、额外结算和绝技的触发顺序。
- 每个加算区的软上限/硬上限，以及独立乘区的准入条件。
- 最终伤害最低是否为0或1。

### 6.2 护盾、治疗、毒火与重伤

必须建立统一的状态表：

| 状态 | 施加单位 | 结算间隔 | 持续/衰减 | 上限 | 穿盾 | 受通用增伤 | 取整时点 |
|------|----------|----------|-----------|------|------|------------|----------|
| 护盾 | 数值 | 无周期结算 | 不自然衰减，承伤/主动移除/战斗结束时减少 | 无统一上限 | — | — | 逐次承伤 |
| 毒伤 | 层 | [待定] | 每次结算线性减少 | 9 | 是 | 否 | [待定] |
| 火伤 | 层 | [待定] | 每次结算减半 | 无 | 否 | 否 | [待定] |
| 重伤 | 时间/层 | [待定] | 随时间递减 | [待定] | — | — | [待定] |
| 持续治疗 | 数值 | [待定] | [待定] | [待定] | — | — | [待定] |

后续数值阶段需要校验：火伤现行向下取整、毒层每次线性-1、重伤治疗削减50%的初稿是否合适，以及持续治疗的间隔与上限。

### 6.3 全局取整和边界

所有系统统一写一份规则，不允许各卡牌自行决定：

- 中间过程保留精度，还是每个乘区后取整。
- 正数向下/四舍五入/向上取整。
- 百分比持续时间如何转为整数tick。
- 状态刷新采用覆盖、延长、叠加还是取较高值。
- 数值上限、下限和溢出处理。
- 同名能力叠加时的加算/乘算方式。
- 随机权重使用整数权重还是万分比。

推荐只在最终显示和最终结算点取整，中间计算保留固定精度；具体仍需程序实现验证。

## 七、卡牌数值框架

### 7.1 每张卡必须有的数据字段

| 字段组 | 字段 |
|--------|------|
| 身份 | CardID、名称、类别、等级、源神石、是否衍生/伙伴/负面牌 |
| 资源 | 费用、X费规则、是否消耗、消耗次数、牌区去向 |
| 基础效果 | 伤害、段数、护盾、治疗、状态量、持续tick、间隔tick |
| 条件效果 | 条件、阈值、追加值、上限、失败时效果 |
| 运转 | 固有、保留、轻盈、抽牌、生成、变化、自动打出限制 |
| 成长 | 一级→二级增幅、三级分支预算、永久成长上限 |
| 统计 | 使用率、主动选择率、弃置率、伤害/防御贡献、持有胜率 |
| 版本 | 规则版本、数值版本、修改原因、测试样本量 |

### 7.2 一级、二级、三级的预算关系

需要先规定等级提升目标，而不是逐张随意加数：

```text
二级基础牌价值 = 一级基础牌价值 × [升级系数待定]
三级牌价值 = 二级基础牌价值 × [分支系数待定] + 机制协同价值
```

三级卡不应只比二级牌数字更大，还要承担Build启动、引擎或终端角色。每张三级卡应标注：

- 启动件：让某体系开始工作。
- 引擎件：持续产资源或状态。
- 桥梁件：连接两个体系。
- 终端件：消耗已有资源造成高收益。
- 通用件：不依赖Build也可稳定使用。

同一体系必须同时拥有启动、生存、资源和终端，但不能只靠一张牌自我闭环。

### 7.3 费用档预算

每个费用档分别建立无条件基准与风险加成：

| 费用 | 基础定位 | 必须额外考虑 |
|------|----------|--------------|
| 0费 | 运转、生成物、小效果 | 占手牌位、打一弃二、轻盈/消耗带来的循环差异 |
| 1费 | 主力标准牌 | 作为SEV主要锚点 |
| 2费 | 强效果或复合效果 | 卡手风险、等待时间、错过敌方窗口 |
| 3费 | 满潮爆发/关键防守 | 命潮归零后的真空期 |
| X费 | 可伸缩终端 | 每点边际收益、0点能否打出、满潮额外奖励 |

高费用牌的总价值可以高，但单位命潮效率不应在无条件下同时碾压低费牌，否则低费牌只剩过渡用途。

### 7.4 特殊词条的隐性预算

- **固有**：提高首轮或指定轮次出现率，应扣除部分面板价值。
- **保留**：提高等待关键窗口的能力，但占据后续手牌位；价值取决于卡组厚度。
- **轻盈**：减少弃牌并提高连续出牌机会，通常是明显正价值。
- **消耗**：既是一次性代价，也是压缩牌组/触发联动的收益，不能一律按负面定价。
- **虚无**：允许高质量，但弃置消失会改变卡组密度并触发消耗联动。
- **奇巧/激发**：必须分别计算主动与弃置两条期望价值，避免“怎么选都赚且无取舍”。
- **能力**：按预期剩余战斗时间计算回本时点；Boss战和普通战价值会不同。
- **生成牌**：不仅计算生成牌面板，还要计算放入抽牌堆/弃牌堆/牌堆顶的速度差异。

## 八、伙伴与共享生命成长

### 8.1 每名伙伴需要先做“基础包”

在设计三分支前，每名伙伴先完成：

1. 1张基础技能牌的完整非分支卡面。
2. 1张基础绝技牌的完整非分支卡面。
3. 明确且稳定的蓄势3触发事件。
4. 1件专属饰品的基础机制。
5. 加入时共享生命增量。
6. 每级共享生命增量。
7. 专属饰品升品等级。
8. 技能、绝技分支解锁等级。

### 8.2 伙伴强度预算拆分

```text
伙伴总战力 = 两张专属卡的牌组价值
           + 专属饰品价值
           + 加入/升级带来的共享生命
           + 分支解锁价值
           - 固定牌组膨胀成本
```

伙伴加入会同时增加战力与牌组厚度，不能只算正收益。若伙伴牌无法删除、复制或普通升级，它们的基础强度必须在整局各阶段都不过时。

### 8.3 蓄势3的频率标准

每个绝技都应记录：

- 触发事件在标准牌组中每分钟发生几次。
- 首次绝技预计在战斗第几秒进入牌组。
- 普通战、Boss战平均能释放几次。
- Build适配时的上限频率。
- 绝技置顶和固有对普通抽牌造成的挤占。

不能只统一“蓄势3”就认为频率相同；触发事件的自然发生率才决定绝技真实强度。

## 九、敌人数值框架

### 9.1 先做四个测试模板

完整敌人内容前，至少建立：

1. **前期木桩敌人**：攻击+防守，验证基础DPS和防御。
2. **中期机制敌人**：加入增幅或状态，验证净化、减速、打断。
3. **后期压力敌人**：行动池升级，验证Build完整度。
4. **Boss测试模板**：两阶段或行动池升级，验证长战与能力牌价值。

### 9.2 每个敌人需要的数据

| 字段组 | 字段 |
|--------|------|
| 基础 | EnemyID、层级、域序、品质、生命、初始状态 |
| 行动 | ActionID、名称、前摇tick、效果、权重、冷却、连续使用限制 |
| 意图 | 玩家能提前看到的伤害/状态/阶段信息 |
| 控制 | 可否打断、减速效率、控制抗性、被打断后的重选规则 |
| 阶段 | 转阶段阈值、强制行动、行动池变化、清状态规则 |
| 奖励 | 胜利/失败奖励、纽币、卡牌、饰品、伙伴成长 |
| 统计 | 平均战斗时长、完成行动数、造成伤害、击败率、主要死因 |

### 9.3 敌方行动预算

每项行动用同一套“压力值”估算：

```text
行动压力 = 直接生命伤害
         + 护盾消耗等价值
         + 状态造成的未来损失
         + 污染牌导致的牌组机会损失
         - 给玩家的反应时间价值
         - 可打断/可净化带来的反制折扣
```

不可打断、短前摇、不可净化和隐藏信息都属于增值条件，不能再配同档最高面板。打断后的敌人重选必须有限制，否则可能被反复刷到最弱行动或无限控制。

## 十一、节点投放与随机规则

### 11.1 每域期望值

每域只有3个探索节点，单个节点权重会显著影响整局。必须计算：

```text
某类节点每域期望次数 = 3 × 该节点最终出现概率
整局期望次数 = 9 × 每域期望次数（再考虑域序修正）
```

需定义：

- 六类节点的基础权重及随域序的变化。
- 普通/稀有/传说的概率，以及“随机节点提高品质”的具体规则。
- 三选一路径是否允许同类重复。
- 随机节点是否提前显示最终类型与品质。
- 保底规则：连续多少域未见商店/营地/战斗后触发保底。
- Boss固定占位是否参与节点品质和奖励档。

### 11.2 奖励价值统一化

将所有奖励换算为“局内战力价值”和“经济价值”两列：

| 奖励 | 局内战力价值 | 纽币等价 | 延迟/随机折扣 | 备注 |
|------|--------------|----------|---------------|------|
| 获得一级卡 | [待定] | [待定] | 三选一命中率 | 可入组或同名合成 |
| 获得二级卡 | [待定] | [待定] | [待定] | [待定] |
| 锻造升1级 | [待定] | [待定] | 需有可升级目标 | 营地三选一 |
| 伙伴温存 | [待定] | [待定] | 伙伴阶段差异 | 同时影响卡、饰品、生命 |
| 随机饰品 | [待定] | [待定] | 槽位/流派不匹配 | 无背包，错配损失更高 |

## 十二、纽币与商店经济

### 12.1 先做产消闭环

```text
整局纽币净变化 = 战斗/事件/挖掘/出售收入
                 - 买卡/买饰品/刷新/锤子支出
```

需要按第1—9域分别记录：进入商店前平均持币、一次商店平均消费、买不起率、离店剩余和终局剩余。

### 12.2 商店需要确定的基础参数

- 一级/二级卡基础价格与域序、品质修正。
- 三档饰品价格与稀有度权重。
- 首次刷新费、连续刷新涨价规则和次数上限。
- 锤子价格、每店次数上限、对不同卡级是否同价。
- 饰品基础回收价、商店品质加成、是否保留v0.6跨店升值规则。
- 商品重复规则、已拥有卡/饰品的出现修正。
- 葛朗台解锁门槛X必须在完整经济模拟后确定，不能先拍脑袋。

### 12.3 经济健康指标

- 正常玩家每次进店至少能做一次有意义选择，而不是长期什么都买不起。
- 玩家不能稳定买空全部商品，否则选择性和货币意义消失。
- 刷新必须是“为Build找牌”的选择，而不是期望收益永远高于直接购买。
- 锤子既能优化牌组也能制造0级卡风险，其价格需结合降级链整体测试。
- 因无背包，饰品错配与被迫丢弃率应被统计；过高代表投放在制造挫败而非选择。

## 十三、饰品数值框架

### 13.1 先确定品质成长方式

三种品质必须先选一种统一原则：

1. **纯数值升级**：机制不变，只提高参数。易平衡、易理解，推荐作为多数饰品的规则。
2. **数值+阈值升级**：高品质降低触发阈值或增加次数。表现明显，但容易改变触发频率。
3. **机制升级**：高品质增加新效果。最有惊喜，但制作和平衡成本最高，只适合少量核心饰品。

建议以“纯数值升级”为主，少量源神石、专属饰品承担机制升级，避免三档实际变成三套不同物品。

### 13.2 饰品预算要考虑槽位

最终四人队共有最多12个角色槽位，但专属饰品、绝境石和特定携带者条件都会占用槽位。每件饰品必须记录：

- 基础效果、触发频率、单次价值、每战总价值。
- 品质倍率或机制变化。
- 是否全队共享、是否要求特定携带者。
- 与同名饰品能否叠加、叠加方式和上限。
- 获取域序、掉落来源、出现权重、商店价格、回收价。
- 在12槽环境中的预期替换时点。

绝境石还应单独验证：它由失败产生，必须能制造“背水翻盘机会”，但不能强到玩家主动追求碎满九石成为最优路线。

## 十四、局外成长与九重轮回

局外数值最后做，因为它会放大所有局内误差。

### 14.1 逸尘经济

先重新确认v0.7下源神石既是饰品又可能关联逸尘时的结算规则，避免“已装备石是否被转化”等旧规则冲突。然后确定：

- 首次失败、普通通关、完整通关的逸尘期望。
- 每个命纹树节点需要几局获得。
- 新手前几局是否持续有可见解锁。
- 图鉴一次性奖励占总逸尘的比例。
- 高轮回倍率是否会让低轮回失去游玩价值。

### 14.2 强运枝边界

强运属于永久数值优势，建议遵守：

- 不改变手牌3、命潮上限3、命源石9等结构常数。
- 不让满树玩家相对新玩家形成接近翻倍的纯战力差。
- 优先提供开局稳定性、选择质量和小额经济，而非粗暴伤害倍率。
- 平衡基准同时保存“零局外成长”和“目标成长进度”两套Build线。

### 14.3 九重轮回

不要只按百分比叠敌方生命。每重应明确测试目标：

- 生命提高检验持续输出。
- 攻击提高检验防御与失误容忍。
- 行动加速检验实时应对和减速价值。
- 污染提高检验牌组处理。
- Boss行动池升级检验机制理解。

多个修正叠加时必须计算总乘积，避免后几重出现非预期指数膨胀。

## 十五、随机性、保底与防刷规则

肉鸽允许强弱局，但必须区分“可控随机”和“无解随机”。至少定义：

- 探索三选一固定从六类中抽取3个不同类型；后续只需校验各类型权重和连续重复保护是否必要。
- 卡牌三选一的同类/同名/源神石权重。
- 二级升三级的九随机三不重复；后续只需决定是否保持完全等权。
- Boss源神石与普通饰品的掉落保底。
- 商店连续刷新后的重复保护。
- 九名伙伴分成三组且全局不重复；后续只需评估完全随机分组是否需要队伍类型软保护。
- 普通战、精英与Boss失败都只获得纽币，需用奖励量和时间成本防止故意失败刷收益。
- 事件负收益是否提前提示，是否允许造成不可挽回的死局。

保底不是让每局都一样，而是确保玩家能通过路线、商店和奖励选择至少形成一个可用Build。

## 十七、测试与数据指标

### 17.1 自动模拟先测数学底线

自动模拟可先忽略复杂玩家策略，验证：

- 初始牌组抽到攻击/防御的概率。
- 各卡在不同牌组厚度下的平均出现间隔。
- 命潮产生、花费和溢出率。
- 敌人行动次数、平均DPS和爆发峰值。
- 毒火、能力牌、永久成长在不同时长下的收益曲线。
- 九域奖励后牌组等级、伙伴等级、饰品数和持币分布。
- 强Build与弱Build的差距是否超出敌人覆盖范围。

### 17.2 人工测试观察体验

人工测试主要回答模拟难以回答的问题：

- 玩家是否看得懂敌方意图并来得及应对。
- 三张牌中是否经常“没有任何有意义的选择”。
- 等命潮的空窗是否过长，或0费连锁是否造成操作轰炸。
- 打断、净化和治疗是否有清晰的最佳时机。
- Build成形后是否真正改变打法，而不只是数字变大。
- 失败能否让玩家理解原因，而不是只感觉敌人突然秒杀。

### 17.3 最低埋点清单

| 层级 | 指标 |
|------|------|
| 单卡 | 出现次数、主动选择率、弃置率、打出时费用、伤害/护盾/治疗贡献 |
| 牌组 | 牌组厚度、各等级数量、0级卡数量、洗牌次数、关键牌平均出现间隔 |
| 资源 | 命潮产出、消耗、溢出、免费牌次数、等待时长 |
| 状态 | 施加量、有效量、溢出量、净化量、实际覆盖时长 |
| 战斗 | 时长、敌我行动数、承伤、过量治疗、剩余生命、胜负和死因 |
| 敌人 | 每个行动选择/完成/被打断次数、各行动造成的实际压力 |
| 冒险 | 节点选择率、域序、奖励选择、商店消费、丢弃饰品和战败位置 |
| 构筑 | 关键卡/饰品组合、Build标签、各域胜率、最终通关率 |

不要单看“持有某卡时胜率”。强玩家更会选择复杂卡，稀有卡又常在强局中出现，必须同时看获得时点、使用率、伤害贡献和相同Build内对照。

## 二十二、基础战斗MVP（第一轮原型）

> 本节记录第一轮可运行原型的目标、边界与暂定默认值。暂定值只用于验证战斗节奏，均可通过原型调参面板修改，不代表最终拍板数值。

### 22.1 已确定的体验目标

| 项目 | 第一轮目标 |
|------|------------|
| 非Boss战时长 | 15—30秒 |
| Boss战时长 | 30—45秒 |
| 单轮回战斗场数 | 约12—15场 |
| 单轮回总时长 | 约15—20分钟，包含战斗、路径、奖励和选择时间 |
| 非Boss主动出牌数 | 约7—10张 |
| Boss主动出牌数 | 约15—20张 |
| 初始共享生命 | 100 |
| 敌我强度关系 | 敌我生命量级接近、有效DPS量级接近，由主动防御与出牌选择决定胜负 |
| 基础命潮恢复 | 每2秒恢复1点 |
| 初始卡牌范围 | 只验证打击、防御；整备及天赋树暂不进入第一轮MVP |
| 其他状态 | 毒伤、火伤、增减伤、治疗、控制等暂不制作 |

### 22.2 目标之间的换算检查

在所有基础牌均为1费、初始命潮为0且每2秒恢复1点时：

```text
15秒理论自然命潮 = 7.5点
30秒理论自然命潮 = 15点
45秒理论自然命潮 = 22.5点
```

因此：

- 非Boss战7—10张牌天然对应约14—20秒的主要战斗区间，符合15—30秒目标；接近30秒的战斗应来自防御、敌方护盾或较差的进攻牌序，而不是单纯等待命潮。
- Boss战15—20张牌天然对应约30—40秒，符合30—45秒目标。
- 若以后增加初始命潮、0费牌、回潮牌或免费牌，实际出牌数会明显提高，必须重新检查时长与出牌数目标。
- 如果大量时间处于满命潮，说明玩家决策/操作跟不上回能；如果长期无牌可打，说明回能或费用过紧。

### 22.3 第一轮暂定默认值

| 参数 | MVP默认值 | 暂定理由 |
|------|-----------|----------|
| 玩家生命 | 100 | 使用已提出的初始生命锚点 |
| 敌人生命 | 100 | 先验证敌我相近量级 |
| 命潮上限 | 3 | 沿用现行结构常数 |
| 初始命潮 | 0 | 让2秒/点与目标出牌数直接对应 |
| 回潮时间 | 2秒/点 | 使用已提出的基础恢复速度 |
| 手牌 | 3张 | 沿用抽三打一弃二 |
| 打击数量 | 7张 | 与3张防御组成10张测试牌组，使普通战出牌数靠近7—10张 |
| 防御数量 | 3张 | 保留基础防御决策，但不让防御牌把战斗普遍拖出目标区间 |
| 打击费用/伤害 | 1费/14伤害 | 约8次无护盾命中击败100生命敌人 |
| 防御费用/护盾 | 1费/12护盾 | 第一轮采用与打击相同面板便于比较 |
| 敌方行动间隔 | 3秒 | 比玩家回潮慢，单次效果相应更高 |
| 敌方攻击伤害 | 20 | 按70%攻击概率和3秒行动间隔计算，期望原始DPS约4.67，更接近玩家实际输出压力 |
| 敌方防御护盾 | 10 | 延长少量战斗时间，但避免一次防御稳定多增加一张出牌 |
| 敌方攻击概率 | 70% | 保证攻击是主要行为，同时测试敌方护盾 |
| 护盾规则 | 先于生命承伤、可累积、不自然衰减 | 第一轮只验证攻防闭环 |

以上默认值不能直接写入最终卡表。完成至少一轮原型测试后，应根据中位战斗时长、出牌数、玩家剩余生命和命潮溢出率调整。

### 22.4 MVP包含的功能

1. 玩家与单一敌人各有生命和护盾。
2. 命潮从初始值开始，按设定秒数恢复，上限为3。
3. 牌组只包含打击和防御，数量、费用和效果均可设置。
4. 每次补足3张手牌；主动打出1张后，本组3张全部进入弃牌堆，再补足下一组；抽牌堆为空时重洗弃牌堆。
5. 打击先消耗目标护盾，剩余伤害扣生命；防御增加自身护盾。
6. 敌人公开下一次意图与行动进度，行动完成后按权重选择打击或防御。
7. 任一方生命归零立即结束战斗。
8. 记录战斗时间、玩家出牌数、敌方行动数、伤害、承伤、护盾和命潮溢出等基础统计。
9. 提供暂停、继续、重开和应用参数后重置战斗。

### 22.5 MVP暂不包含的功能

- Boss阶段机制、九域流程、奖励、商店、营地和局外成长。
- 伙伴、身份、饰品、源神石和命源石损伤。
- 整备、天赋树、卡牌升级与三级分支。
- 毒火、治疗、力量、鼓舞、激昂、易伤、脆弱、减速和打断。
- 负面状态牌、特殊词条和衍生牌；护盾自然衰减已从正式规则移除。
- 正式美术、剧情和账号存档。

| 模块 | 可调参数 |
|------|----------|
| 玩家 | 最大生命、初始护盾 |
| 敌人 | 最大生命、初始护盾、行动间隔、攻击概率、攻击伤害、防御护盾 |
| 命潮 | 上限、初始值、每点恢复秒数 |

### 22.8 第一轮验收标准

- [ ] 默认配置下可从开战持续运行到明确胜负，不出现卡死或牌堆耗尽。
- [ ] 命潮严格按配置恢复且不超过上限。
- [ ] 每次只可主动打1张，另外2张随本组进入弃牌堆，随后手牌补足3张。
- [ ] 护盾正确先于生命承担伤害。
- [ ] 敌方意图和进度可见，打击/防御按配置执行。
- [ ] 所有调参项应用后立即以新参数重开。
- [ ] 默认非Boss测试的时间和出牌数能接近15—30秒、7—10张的目标区间。
- [ ] 页面在常见桌面宽度和窄屏下均可完成出牌与调参。

### 22.9 默认参数的初步模拟结果

使用“有打击优先打击，否则打出可用防御”的简单自动策略进行批量模拟，用于检查默认参数是否明显偏离体验目标。模拟不是玩家真实胜率结论，只是数学冒烟测试。

- 5打击+5防御、打击12的早期默认方案：战斗中位时长约24秒，但平均主动出牌超过12张，不符合非Boss战7—10张目标。
- 调整为7打击+3防御、打击14、敌方攻击20、敌方防御10后，5000次简单策略模拟的战斗中位时长约18秒、P90约20秒、平均主动出牌约8.7张，进入第一轮目标区间。
- 同一简单策略模拟胜率约83%、胜负结束时平均剩余生命约23；这只是压力基线，不代表真实玩家目标胜率。

因此当前MVP使用第二组参数作为测试起点，但不得据此认定7:3牌组比例、14点打击或20点敌方攻击已经定稿。
