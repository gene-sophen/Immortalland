## 一、参照系与时长定位

| 游戏 | 单场时长 | 张力来源 | 我们能抄什么 |
|------|----------|----------|--------------|
| 云顶之弈 | 20-40秒 | 战前摆位博弈+加时赛机制 | 战斗要短；加时给增益逼出结果 |

## 二、"加速"一体化设计（本系统的核心手法）

加速是我们解决节奏问题的总开关，四种加速各管一段：

| 加速类型 | 作用 | 服务对象 |
|----------|------|----------|
| **倍速开关**（1x/2x/3x） | 压缩低难度战斗的现实耗时 | 玩家体验（杂兵战15秒结束） |
| **源能分幕加速**（1x→1.5x→2x） | 战斗中后期能量变快，适配成型卡组的高费消耗 | 节奏曲线（皇室双倍圣水逻辑） |
| **加时增益**（见第三节） | 拖入加时时全场攻速/伤害递增 | 防拖局（云顶加时逻辑） |
| **子弹时间**（见第五节） | 反向加速：操作时时间变慢 | 操作兜底 |

有数值难度（加时增益）和子弹时间兜底，加速永远站在玩家这边。

## 三、单场战斗的三幕结构 + 加时赛

| 幕 | 时间段 | 源能回复 | 内容 |
|----|--------|----------|------|
| **第一幕·接触** | 0-20秒 | 1点/2秒（1x） | 前排交火，技能干预开局走向 |
| **第二幕·交换** | 20-40秒 | 1点/1.3秒（1.5x） | 精英/敌方技能前摇出现，决策密度峰值 |
| **第三幕·决胜** | 40秒后 | 1点/1秒（2x） | 绝技连发窗口 |

### 加时赛（40秒后启动，三层递进）🔶

融合云顶与皇室的加时设计：

1. **全场亢奋**（云顶式）：双方全体攻速+30%，此后每10秒伤害再+25%——拖得越久越危险，数值上逼出结果
2. **源能2x**（皇室式）：见上表第三幕
3. **源神风暴**：45秒后启动，每秒对双方全体造成递增伤害（初始2点/秒，每秒+2，无视护盾）——战斗硬上限约75-90秒

**平局兜底**：同一时刻双方同归于尽时，**判定玩家获胜**（仁慈规则，类似皇室的突然死亡倾向性）🔶。

## 四、时间刻度引擎（0.1秒tick）🔶

实时引擎的所有结算建立在离散时间刻度上：

| 规则 | 内容 |
|------|------|
| **基础刻度** | 1 tick = 0.1秒，所有伤害/回复/持续伤害/冷却/前摇都按tick结算 |
| **时间流速** | 子弹时间/倍速通过timescale实现：0.3x=现实1秒走3个tick的游戏时间；2x=走20个tick。**任何流速下结算时机都是整tick，杜绝浮点争议** |
| **防循环兜底** | 同名触发效果**每tick最多结算1次、每秒最多3次**——引擎层封杀无限循环，不需要单卡逐个防范 |
| **攻速兜底** | 攻击间隔下限0.5秒（5 tick）——攻速词条堆得再高也有物理上限 |
| **前摇/读条** | 以tick数标注（如敌方技能前摇15 tick=1.5秒），慢动作下tick等比拉长，玩家反应时间可控 |

## 五、子弹时间与操作

| 操作 | 时间流速 |
|------|----------|
| 点住手牌（选牌） | 0.5x |
| 拖拽瞄准目标格 | 0.3x，按住不限时 |
| 松手施放 | 恢复1x |

辅助档位：**标准**（0.3x瞄准）/ **轻松**（瞄准时完全暂停）/ **自动**（绝技自动释放）。

一次施放真实耗时1.5-3秒，游戏时间只走0.5-1秒；由于tick引擎，慢动作下的结算时机依然精确（见第四节）。

## 六、绝技系统（蓝条入卡组方案）v1.1重写 🔶

**取消独立TP槽，改为云顶式蓝条：**

| 规则 | 内容 |
|------|------|
| 蓝条 | 每名伙伴英雄一条（长度80-120点，按伙伴定位调节：激进位短、辅助位长） |
| 充能方式 | **动作充能，不走时间**：普攻命中+10、承受伤害按比例、施放技能牌+少量 🔶——多动作多充能，避免干等 |
| 充满后 | **绝技牌进入手牌区**（见下方两种呈现方案），蓝条锁定，施放后清零重新充能 |
| 费用 | **0源能**——蓝条本身就是成本，不被源能二次收费 |
| 主角 | 无绝技，身份牌在卡组中正常循环 |

**绝技牌呈现方案（二选一）**🔶：
- 方案A：**独立绝技格**——手牌区上方出现金色第4格，点击即瞄准施放。优点：即时、清晰、有仪式感
- 方案B：**置入牌堆顶**——充满后下一次摸牌必摸到（你的原始构想）。优点：完全复用卡组机制；缺点：需要腾出手牌位才摸得到，节奏可能卡顿

建议方案A，方案B的"摸牌期待感"可以留给特定伙伴（如诺瓦）作为个人机制差异。

## 九、数值体系：100数量级 + TTK锚 v1.1重写

**数值规模**：维持原100数量级（英雄血30-60、杂兵血18-35、精英50-90、Boss 130-260）。

** chunky攻击模型**：实时引擎下不用"高攻速小数字"，用**低攻速大数字**——

| 参数 | 设计 |
|------|------|
| 每击伤害 | = 攻击力（整数，大数字快感） |
| 攻击间隔 | 按职业2.5-4秒（刺客2.5s、战士3s、法师3.5s、骑士4s）🔶，攻速词条按%缩短间隔（下限0.5秒） |
| TTK锚 | 杂兵双英雄集火8-10秒、精英全队25-30秒、Boss全程60-75秒 |

**取整与百分比纪律**（v1.1新增）：

1. **规避低百分比**：系数只取50%/100%/150%/200%档；词条增益只取25%/50%档——杜绝3%、7%这类四舍五入争议 🔶
2. **衰减等修正值独立设计**：不写全局公式，印在牌面/面板上（如贯矢"每格−2伤害"、某敌人"远程伤害−5"）——每个伤害源的衰减是独立数值，调平衡不动公式
3. **统一向下取整**，且设计数值时优先保证整数结果（偶数基数配50%系数等）
4. 技能牌价值锚：**1点源能 ≈ 1.5-2秒全队自动输出**
